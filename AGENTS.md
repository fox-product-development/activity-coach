# Activity Coach — Project Context for AI Assistants

## What This App Does

A personal activity coaching web app that tracks activities, mood, diet and weight, and proactively emails personalised daily suggestions each morning via an AI agent. A weekly summary email is also sent every Sunday evening.

## Tech Stack

- **Framework:** Next.js 16 (App Router, TypeScript, Tailwind)
- **Database:** Supabase (PostgreSQL + Auth)
- **Hosting:** Vercel (with cron jobs)
- **Email:** Resend (from coach@activitycoach.co.uk)
- **Weather:** Open-Meteo (free, no API key)
- **AI:** Claude API via @anthropic-ai/sdk (claude-sonnet-4-6)
- **Auth:** Supabase Auth with Google OAuth

## Live URLs

- Production: https://www.activitycoach.co.uk

## Database Tables

- **activities** — logged activities per user (type, date, duration, metrics)
- **activity_types** — global library of activity types (shared, no user_id)
- **user_activities** — per-user enabled activity types
- **mood_logs** — daily mood and energy check-ins (1-5 scale)
- **diet_logs** — daily diet (from Nutra Check screenshots) and weight
- **agent_suggestions** — daily suggestions generated by Claude
- **settings** — key/value store per user (goal, kung_fu_enabled, kung_fu_sash)
- **kung_fu_elements** — shared library of Kung Fu practice elements
- **allowed_users** — email whitelist for app access

## Key Patterns

### Authentication

- Google OAuth via Supabase Auth
- `proxy.ts` protects all routes — redirects to `/login` if no session
- `getServerUser()` in `lib/supabase.ts` gets current user in API routes
- All personal tables have `user_id uuid references auth.users(id)`
- Allowed users whitelist in `allowed_users` table

### API Routes

- All routes call `getServerUser()` first and return 401 if not authenticated
- All queries filter by `user_id` for personal data
- `createServerSupabaseClient()` used in all API routes (service role key)
- `supabase` browser client used only in `app/login/page.tsx`

### Supabase Client

- `createServerSupabaseClient()` — server only, full access
- `getServerUser()` — gets authenticated user from cookies
- Both exported from `lib/supabase.ts`

### Image Extraction

- Activities: Garmin/Strava screenshots → `lib/activities.ts` → Claude vision
- Diet: Nutra Check screenshots → `app/api/diet/route.ts` → Claude vision
- Date parsing handles "Today", "Yesterday", and specific dates with timezone fix

### Cron Jobs (vercel.json)

- `/api/email` — 4am UTC daily (daily suggestion for all users)
- `/api/weekly` — 7pm UTC Sundays (weekly summary for all users)
- `/api/email/me` — Feb 31st (impossible date, manual trigger only)

## Multi-User

- Two users currently: owner and wife
- Wife has kung_fu_enabled = false
- Wife has different user_activities (no cycling, fishing)
- All data separated by user_id with RLS policies

## Kung Fu Feature

- Completely separate from regular activities
- Controlled by `kung_fu_enabled` setting (default false)
- `kung_fu_sash` setting controls available elements (red/yellow/next)
- Elements stored in `kung_fu_elements` table (shared)
- Daily: Qi Gong (always) + one rotating element
- Shown in: home page section, daily email (dark box), agent reasoning
- Lung Ying style — practice elements are lineage-specific

## Activity Types System

- `activity_types` — global library (name, type_key, is_outdoor, emoji)
- `user_activities` — per-user enabled activities
- Agent reads from these tables (not hardcoded)
- Users can add/remove via "Manage Activities" popup in app
- Custom activities added by user go to both tables
- If no other users have a custom activity and it's removed, deleted from activity_types too
- Gym excluded on weekends (office gym)

## Daily Email Format

1. Stats box (sessions, mins, mood, energy, kcal, protein)
2. Yesterday recap
3. Today's suggestion
4. Today's activity (yellow box)
5. Kung Fu recommendation (dark box, only if enabled)

## Weekly Email Format

1. Week at a glance stats box
2. Sectioned body with bold openers and HR dividers
3. This week's focus box (yellow)
